# Roster 📋

**Roster** is the atomic UI component library powering the **MegaSquad** ecosystem.

It is built with **React 19**, **TypeScript**, **Tailwind CSS v4**, and **Vite**, offering a set of high-quality, accessible, and theme-aware components.

## 🚀 Features

- **Next.js App Router Ready:** All components are automatically bundled with `"use client"` directives for seamless SSR integration without context crashes.
- **Decoupled Theming:** Bring your own brand. Roster ships structural CSS separately from its default design tokens, allowing you to easily override CSS variables or use the default MegaSquad theme.
- **Atomic Design:** Components organized by atoms, molecules, and organisms.
- **TypeScript First:** Fully typed for excellent developer experience (DX).
- **Adaptive Dark Mode:** Fully supports manual, class-based dark mode toggling (`.dark`) independent of OS preferences.
- **Headless UI:** Accessible interactive components powered by `@headlessui/react`.
- **Tree-Shakeable:** Import only what you need.

## 📦 Installation

```bash
npm install @blakesteve/roster
# or
yarn add @blakesteve/roster
```

### Peer Dependencies

Roster needs React in your host application:

```json
"peerDependencies": {
  "react": "^19.0.0",
  "react-dom": "^19.0.0"
}
```

Tailwind is **not** required — Roster ships pre-compiled CSS.

## 💻 Usage

### 1. Import Styles

Roster splits its CSS so you keep full control of your theme. Import it once at
the root of your application (`layout.tsx`, `main.tsx`, or `App.tsx`).

```tsx
// Required: the compiled component styles
import "@blakesteve/roster/style.css";

// Optional: the default design tokens
// (Omit this if you define your own --roster-* variables in your global CSS)
import "@blakesteve/roster/tokens.css";
```

#### Cascade layers

Roster's styles live in a `roster` cascade layer, and it declares the full layer
order itself, so importing it is normally all you need:

```css
/* globals.css */
@import "@blakesteve/roster/tokens.css";
@import "@blakesteve/roster/style.css";
@import "tailwindcss";
```

The declared order is:

```css
@layer roster-preflight, theme, base, components, roster, utilities;
```

`roster` has to sit exactly there. **Above `base`**, because Tailwind's preflight
resets `*{margin:0;padding:0;border:0 solid}`; put Roster below it and that reset
outranks Roster's own spacing and border utilities, stripping padding off buttons
and turning `border-transparent` into a visible 1px line. **Below `utilities`**,
so your app's classes and variants like `dark:hidden` still win.

Layers are ordered by *first registration*, so importing Roster ahead of Tailwind
is the reliable arrangement. To stop depending on import order entirely, declare
that same line at the top of your own global stylesheet.

#### The global reset is opt-in

Roster ships **no preflight**. A component library has no business resetting its
host's document, so importing Roster will not touch your headings, lists, or box
sizing.

Roster's components do assume that normalization exists. If your app runs
Tailwind you already have it. If it does not — a plain Vite app, a Storybook, an
app with no reset of its own — opt in, before the component styles:

```tsx
import "@blakesteve/roster/preflight.css";
import "@blakesteve/roster/style.css";
```

Skip it and components render against browser defaults: serif type, bulleted
lists, `content-box` sizing. This Storybook imports it for exactly that reason —
see `.storybook/preview.ts`.

### 2. Import Components

Now you can use the components anywhere in your app.

```tsx
import { Button, Spinner } from "@blakesteve/roster";

function App() {
  return (
    <div className="p-4 flex flex-col gap-4">
      {/* Primary Button */}
      <Button colorScheme="primary" onClick={() => alert("Clicked!")}>
        Save Changes
      </Button>

      {/* Destructive Variant */}
      <Button colorScheme="error" variant="outline">
        Delete Account
      </Button>

      {/* Loading State */}
      <Button isLoading>Processing...</Button>

      {/* Standalone Spinner */}
      <Spinner size="lg" />
    </div>
  );
}
```

## 🎨 Development

We use **Storybook** to develop and document components in isolation.

```bash
# Install dependencies
npm install

# Start Storybook
npm run storybook
```

This will open the component playground at http://localhost:6006.

## 🛠️ Building

To build the library for production (outputs to `dist/`):

```bash
npm run build
```

This generates:

- `dist/roster.es.js` (Main library ES Modules)
- `dist/tokens.es.js` (Token injection script)
- `dist/data-table.es.js` (DataTable entry; keeps the TanStack import out of the main bundle)
- `dist/roster.css` (Compiled component styles, in the `roster` cascade layer)
- `dist/tokens.css` (Design token CSS variables)
- `dist/preflight.css` (Optional global reset — see Import Styles above)
- `dist/index.d.ts` (Type definitions)
